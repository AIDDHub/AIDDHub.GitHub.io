# 写内容

这个站是「Markdown → 静态 HTML」的。你只需要写 Markdown，GitHub Actions 会在部署时自动构建，
不需要在本地跑任何脚本。

> 英文版说明见根目录 `README.md`；这份是中文操作手册。

---

## 1. 内容分三类

| 类型 | 位置 | 出现在 |
|---|---|---|
| 文章（随笔 / 教程） | `content/posts/` | 首页列表、`/notes/` 或 `/tutorials/` |
| 独立页面 | `content/pages/` | `/about/`、`/projects/` |
| 首页个人资料 | `content/profile.yml` | 首页顶部 |

文章按 `section` 分两类：

- `notes` → `/notes/`，导航里叫 **Writing / 随笔**
- `tutorials` → `/tutorials/`，导航里叫 **Tutorials / 教程**

## 2. 新增一篇文章

### 第 1 步：建文件

路径：

```
content/posts/<slug>.en.md
```

规则：

- `<slug>` 全小写，单词之间用连字符：`reading-notes-2026`
- 必须是 `.en.md` 结尾（中文版是 `.zh.md`）
- slug 会成为 URL：`/notes/reading-notes-2026/`

### 第 2 步：写 front matter 和正文

```markdown
---
title: "Reading notes, autumn 2026"
description: "Four papers on scaffold hopping, and what I took from each of them."
date: 2026-11-20
section: notes
tags: [reading, scaffold-hopping]
---

开头一段。不要写「本文将介绍」，直接进入内容。

## 第一个小标题

正文。每个 `##` 会自动进入右侧目录。

| 列 | 说明 |
|---|---|
| A | 表格也支持 |

> 引用块可以用来放结论或提醒。
```

### 第 3 步：提交并推送

```powershell
git add content/posts/reading-notes-2026.en.md
git commit -m "post: reading notes"
git push
```

约 1 分钟后上线：
`https://aiddhub.github.io/notes/reading-notes-2026/`

---

## 3. front matter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 文章标题，用于 H1、浏览器标题、社交卡片 |
| `description` | 是 | 搜索摘要，建议 120–160 字符 |
| `date` | 是 | 格式必须是 `YYYY-MM-DD` |
| `section` | 是 | `notes` 或 `tutorials` |
| `short_title` | 否 | 面包屑里的短标题，默认从 `title` 截取 |
| `tags` | 否 | 标签列表，会写成 `keywords` |
| `product` | 否 | `molstudio` / `molinsight` / `both`。**不写就不显示软件徽标** |
| `updated` | 否 | 最后更新日期，会写进结构化数据 |
| `draft` | 否 | `true` 时该文件完全不参与构建 |

### 容易写错的地方

- 标题里如果有 `:`，整行必须用引号包住（否则 YAML 报错）
  ```yaml
  title: "Docking: the parts that bite"
  ```
- 日期写成 `2026-11-20`，不要写 `2026/11/20` 或 `11-20`
- `tags` 用方括号加逗号：`[docking, sar]`

## 4. 中文版

复制一份，改成 `.zh.md`，正文换成中文：

```
content/posts/reading-notes-2026.en.md
content/posts/reading-notes-2026.zh.md
```

要求：

- `date`、`section`、`product` 必须和英文版一致（决定排序与徽标）
- `title` / `description` 用中文写
- 不写中文版不会报错，但构建日志会提示：

```
warning: no Chinese edition for: reading-notes-2026
```

> 两边的文章数量会不一致——中文首页只列出有中文版的文章。

## 5. 插图

1. 把图片放进 `assets/img/`
2. 正文里引用：

```markdown
![对接构象的 2D 相互作用图](/assets/img/docking-interactions.png)
```

建议：

- 宽度 1200–1600 px，控制在 500 KB 以内
- 文件名用小写连字符，换图时最好换文件名（GitHub Pages 缓存 10 分钟）
- 不要用绝对外链图片，容易失效

## 6. 改首页

首页所有文字都在 `content/profile.yml`：

```yaml
name: AIDDHub
handle: "@AIDDHub"
avatar: /assets/img/avatar-icon.png

tagline:
  en: "Computational chemistry · drug design · cheminformatics · data analysis"
  zh: "计算化学 / 药物设计 · 化学信息学 / 数据分析"
```

| 字段 | 作用 |
|---|---|
| `name` | 大字标题 |
| `tagline` | 名字下面那行 |
| `intro` | 自我介绍段 |
| `keywords` | 关键词标签 |
| `now` | 「近况」列表 |
| `links` | 链接行（GitHub / Email / RSS …） |
| `avatar` | 头像路径 |

每一项都有 `en:` 和 `zh:` 两套。想换头像，直接覆盖 `assets/img/avatar-icon.png`（方图，300×300 以上）。
这个文件同时用于页眉、页脚和分享卡片，所以最好保持正方形；页面会按 22% 圆角显示，不会裁成圆形。

## 7. 改「关于」「项目」

这两个是普通 Markdown 页面：

## 9. 发布是怎么发生的

```
push 到 main
   ↓
GitHub Actions: 装依赖 → 运行 tools/build_site.py → 上传 _site → 发布
   ↓
https://aiddhub.github.io/   （约 1 分钟）
```

要点：

- **不需要提交生成的 HTML**。CI 会现构建，只提交 Markdown 就行
- 构建失败会在 Actions 页面显示红叉，站点保持上一版
- 改完 Markdown 不等 CI 也能本地预览

## 10. RSS 订阅

每次构建会生成两份订阅文件，内容自动同步，不需要手动维护：

| 文件 | 语言 | 地址 |
|---|---|---|
| `feed.xml` | 英文 | `https://aiddhub.github.io/feed.xml` |
| `zh/feed.xml` | 中文 | `https://aiddhub.github.io/zh/feed.xml` |

- 各取该语言最新的 20 篇，按日期倒序
- 只包含标题、链接、发表日期、摘要
- 页面上的 RSS 链接会根据当前语言指向对应文件
- 新增文章不用做任何操作，下次构建自动出现

## 11. 常见问题

**推上去没变化？**
先看仓库 Actions 页面有没有失败；没有失败就等 1–2 分钟，再 `Ctrl+F5` 强制刷新。

**构建失败了？**
最常见是 YAML 格式：标题里有冒号没加引号、日期格式不对、`tags` 少括号。
Actions 日志里会指出哪个文件、第几行。

**想先写草稿不发布？**
front matter 里加 `draft: true`，构建时会被跳过。写完了删掉这一行。

**改了一篇旧文章要不要改日期？**
不要改 `date`（会改变排序），用 `updated: 2026-11-20`。

**中文页面和英文对不上？**
检查两边 `date` / `section` / `product` 是否一致；slug 必须完全相同。

**能直接照抄别的文章吗？**
可以，复制一篇最接近的，改 slug、标题、日期、正文。记得把 `draft` 删掉。

## Markdown 速查

| 想要 | 写法 |
|---|---|
| 二级标题（进目录） | `## 标题` |
| 三级标题 | `### 标题` |
| 加粗 | `**文字**` |
| 行内代码 | `` `vina` `` |
| 代码块 | 三个反引号包起来，或缩进 4 空格 |
| 列表 | `- 项目` |
| 有序列表 | `1. 项目` |
| 表格 | 见第 2 步示例 |
| 引用 / 提示 | `> 一句话` |
| 链接 | `[文字](https://example.com)` |
| 站内链接 | `[教程](/tutorials/docking-in-10-minutes/)` |
| 图片 | `![说明](/assets/img/x.png)` |
| 分隔线 | `---` |
