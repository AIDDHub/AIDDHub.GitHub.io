10 分钟在 Windows 上跑完一次分子对接（不用 Python）

手上有一个蛋白结构、十几个化合物，明天要给出一个结合模式的假设。常规路线是：装 conda、装 MGLTools、 转换受体、再回忆去年用过的 vina 参数——一个下午就没了，第一个构象还没出来。

这篇把同样的流程放进 MolStudio：导入、准备、对接、看相互作用、导出图。全部在本地跑，Windows 和 Linux 是同一个程序，步骤完全一致。

需要准备什么

  • MolStudio v1.0——下面的每一步都在免费版里
  • 一个受体结构，例如 PDB 的 3FUP.pdb
  • 配体：SDF、SMILES 或 CSV 都行，第一次跑十几二十个就够

1. 导入受体

File → Import → PDB，选文件。MolStudio 会把结构按链、残基、杂原子基团和水分子分开显示，所以在 准备之前就能看清哪些要保留、哪些要丢掉。

导入后先确认两件事：

  • 共晶配体在（下一步要用它定位对接盒子）；
  • 没有因为你没注意的生物组装体而多出来的重复链。

2. 准备受体

Applications → Preparation → Receptor Prep。

默认设置覆盖了大多数对接场景：去结晶水、按 pH 7.4 加氢、分配电荷。这一步是新手最容易翻车的地方—— 不是因为它难，而是因为准备到一半的受体照样能跑出看起来很合理、打分却很差的构象，而输出里不会告诉你原因。

这一步先不要删共晶配体，下一步要用。

3. 导入配体

File → Import → SDF（或 SMILES / CSV）。批量导入后直接进 Molecule Table，每行显示分子量、LogP 以及其它已计算的性质。

名称在这里就改好，别拖到后面：记录标题会成为所有下游表格和导出 SDF 里的配体名。

4. 把盒子放对位置

Applications → Docking 打开对接面板和盒子控制。

  • Pick from 3D——在 3D 视图里点一下结合口袋，盒子以该点为中心；
  • Center on ligands——以共晶配体为中心。已知参考化合物结合位置时，这个选择更容易复现。

边长 22–24 Å 是稳妥的默认值。盒子不是越大越好：盖住半个蛋白只会稀释搜索、拖慢速度。

参数 起步值 什么时候改
Exhaustiveness 8 最终构象用 16–32；200 个化合物先粗看用 4
Number of poses 9 只留前 3 个看构象，其余基本是噪声
CPU 核数 4 长时间跑就用满空闲核
Seed 固定 需要两次结果完全一致时

5. 跑 Vina

点运行。进度会显示，工作区仍然可用——你可以在它跑的时候整理表格、准备下一个受体。10 个配体、 exhaustiveness 8，普通笔记本几分钟就完了。

6. 看结果表

结果表每个构象一行：配体、mode 编号、Vina 打分。大多数人到这里就按打分排序，然后停下了，而这恰恰是 输出里最不重要的部分。

打分函数不是结合自由能。它能用来在同一受体、同一质子化状态下给化合物排序。跨两个不同结构、 或跨两套准备流程比较打分，没有意义。

7. 看构象，不看数字

选中最好的构象，打开 Interactions 面板，切到 2D 视图。MolStudio 会画出氢键及距离、疏水作用、π–π 堆积和盐桥。

问三个问题：

  1. 配体占据的亚口袋和参考化合物一致吗？
  2. 氢键方向对吗？还是 4 Å 的斜向"氢键"？
  3. 起作用的是骨架，还是你正准备优化的取代基？

一个打分 −9.0 但什么也没埋进去的构象，价值低于一个 −7.5 却能解释现有 SAR 的构象。

8. 导出需要的东西

  • 2D 相互作用图导出 PNG 或 SVG，直接进 PPT 或报告；
  • 需要以后叠加比对，就把对接构象导出为 SDF；
  • 整个工作区可以存成会话，下周打开继续，不用重新准备一遍。

常见问题

现象 可能原因 处理
所有配体打分几乎一样 盒子放在浅的、暴露于溶剂的表面 重新定位盒子，先看参考配体
构象穿进蛋白里 受体没做能量优化、缺氢 重做 Receptor Prep，检查组氨酸质子化
同一批化合物重复跑结果不同 没固定 seed 比较之前先固定 seed
打分最好的恰好是你已知无活性的那个 打分函数偏好大分子 按重原子数归一，并回到相互作用看
