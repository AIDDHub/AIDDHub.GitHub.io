一份在用的工具清单

工具清单过时得很快，所以这份带日期，也带一条规则：只写最近一个月真的打开过的，只写会想念的。

化学

RDKit。 任何和结构有关的事，默认答案，而且名副其实。检查一个规范化结果、试写一个描述符， 或者在把 SMARTS 写进代码之前确认"它到底匹配什么"，它都是最快的路径。格式和反应覆盖面上， 没有别的能接近。

ChEMBL。 不是软件，是数据集——但要拿真实系列去检验一个想法时，它是第一个该看的地方。 有合理 SAR 的公开数据，永远胜过合成出来的数据。

DataWarrior。 打开一个陌生 SDF 看一眼，它还是最快的。免费、局部不好看，但在项目开始时最需要的那件事上 非常好用：看见整个集合。

PyMOL。 主要用来出图。不是因为好用，而是因为每个审稿人都认得它的输出。

Open Babel。 偶尔用，处理 RDKit 拒绝的格式转换。它已经很多年不是首选了，仍然装着。

构建

Python 负责界面之外的一切。它是这个生态的语言，和它较劲是爱好，不是策略。

Qt 负责桌面层。成熟、可预测，把那些不体面的部分——停靠面板、表格、高 DPI 缩放——处理得没有戏剧性。

C++ 只在测过之后用。 先剖析，再重写。到目前为止追过的性能问题里，有一半其实是两千个分子的 Python 循环， 而不是算法。

GitHub Actions 用来跑那些能抓住错误的检查：站点还能不能构建、测试在另一台机器上还能不能过。

写作与思考

Obsidian，一个纯 Markdown 文件夹，没有非用不可的插件。它明天坏掉，文件还在，这就是全部意义。

纸质笔记本，给一切带结构式的东西。在触控板上画机理，是一种逃避思考的方式。

被删掉的工具

  • 把 Excel 当数据库。 还会打开；但活性表不再只有它一份。
  • 把 Jupyter notebook 当产品。 探索很好，任何下个月还要再跑一次的东西都很糟。 一个 notebook 一旦有用户，它就想变成一个带参数解析的脚本。
  • 给桌面应用用 Docker。 它解决了一个这里不存在的问题，制造了一个这里存在的支持问题。
  • 第二块屏幕堆满看板。 换成了一页真的会看的数字。

意外的那个

Cloudflare。原本期待的是一个 CDN；实际得到的是一个放静态站、一个下载桶和一个邮件转发的组合， 一个月不到一杯咖啡的钱，没有服务器要打补丁。对一个小工作室来说，这就是全部基础设施预算， 而且到现在还没倒。

还缺的

一个能同时看 3D 结构和活性表、不用 alt-tab 的方法。MolStudio 大致就是因为这个才存在的， 而这个问题还没有完全解决。
