2026 年了，我为什么还在写桌面软件

每隔几个月都会有人问：MolStudio 为什么不是网页版。这个问题很合理——浏览器是软件现在该待的地方， 部署几乎不花力气，用户也不用装任何东西。

我也写过网页项目。但我还是在发布桌面程序，想把原因写下来，包括那些不太好受的部分。

决定形态的是化学，不是流行

一次对接不是一个 HTTP 请求。它是某台机器上二十分钟的 CPU 计算，要能看着进度、中途改参数、 结果是装了一堆构象的文件夹，而不是一个 JSON。

二十万行的化合物表也一样：在浏览器里排序、筛选、聚类当然做得到，但用户一旦想把表拖到第二块屏幕的 绘图窗口里，或者跑一个要四分钟的模型，浏览器就从优势变成了约束。

我在意的工作流是本地、反复、计算密集的。桌面不是怀旧，是问题的形状。

本地安装到底换来了什么

不用上传。 结构、活性表、模型都留在本机。对任何在保密协议下工作的人——也就是手上真有化合物系列的 大多数人——这不是一个卖点，而是能不能用这个工具的前提。

飞机上、地下室、医院内网里都能跑。 工业界和高校的网络里全是代理，什么都要拦。一个装完就能运行的 安装包，比一个需要申请域名白名单的服务容易批得多。

没有延迟预算。 打开 50 MB 的 SDF 花多久，取决于磁盘，不取决于网络。也不用为了省一次往返把界面 分页。

我的服务器挂了，软件还在跑。 这条比较私人。我喜欢三月发出去的版本，十一月还能在一台我从没见过的 机器上打开，不需要我付可用性的钱。

代价

我不想假装这些取舍很小。

  • 分发是税。 每个平台的安装包、代码签名、下载托管，以及杀毒软件厂商哪天改主意之后的一场客服对话。
  • 更新要商量。 网页版所有人都在新版本上；桌面版永远有人停在十八个月前的版本，而他的 bug 报告 说的是你早就不记得的代码。
  • 没有遥测就没有数据。 崩溃是别人发邮件告诉我的。这个反馈闭环比任何仪表盘都差。
  • 凌晨两点你修不了。 服务器上没有热修，只有重新打包、重新上传，再写邮件请大家重装。

这些都是实打实的成本，也是大多数新的科学软件选择网页版的原因。

我的界线

我不认为网页是错的。我认为浏览器是分发渠道，不是计算模型。当一个工具主要是一个表单、一块看板或一个 共享数据库时，它属于网页，也应该留在网页上。当一个工具的核心是视口里的一个分子加 CPU 上的一个求解器， 浏览器就是在原生引擎外面多包了一层，还要付额外的代价。

所以：原生程序、磁盘上的普通文件、不要账号、不同步。如果哪天这个形状不再适合要做的事，我会改。 以前也改过。

一个不体面的优势

还有一个理由，和技术无关。桌面软件在用户不再需要你的时候就算完成了。没有活跃度指标，没有留存曲线， 也没有动机让工具比问题本身更黏人。

我喜欢这个约束。它让设计问题变小，也更容易回答：这东西今天能帮人拿到一个站得住脚的结论吗？ 拿到之后，他可以走开吗？
